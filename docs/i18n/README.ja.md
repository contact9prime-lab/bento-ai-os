**頭脳を宿したあなたのマシン。** Bento Box AI はセルフホスト型の **AI デスクトップ環境**です。ウィンドウ、アプリ、ファイル、ターミナルを備えた完全なデスクトップを、あなたのコンピューター上で**実際に行動する**、**自律的な AI エージェント**が動かします。完全なプライバシーのために [Ollama](https://ollama.com) 経由のローカルモデルを使うことも、クラウドモデル（Anthropic Claude、OpenAI、OpenRouter、あるいは OpenAI 互換の任意のエンドポイント）を使うこともできます。どちらも、常にあなたの承認のもとで動きます。エージェントは Web を閲覧し、自分自身のアプリを作り、ジョブをスケジュールし、学んだことを記憶し、自らのソースコードを拡張し、Telegram や WhatsApp であなたに連絡してきます。

## セットアップは 9 つのステップ。そのどれもが、何かを残していく

進捗バーの付いた設定フォームではありません。どのステップも**実在する何か**を生み出します — 応答するモデル、存在するようになるエージェント、実行されるフロー、発火するスケジュール — そして、あなたに何かを尋ねる前に、あなたが最終的に手にするものを告げます。

![初回セットアップ画面：左側に 9 つのステップが並ぶレール、右側には「エージェントに名前を付ける」と「あなたが最終的に手にするもの：メニューバーとすべての返信に表示される名前」の一行](../screenshots/onboarding-1-name.png)

どのステップも**記憶されるのではなく、その都度確かめられます**：マシンが実際にそれを持っているからこそチェックが付くのです。エージェントを削除すれば、そのステップは未完了に戻ります。だからこそ再実行が安全であり — そして再実行はここでは当たり前の行為です。なぜなら**セットアップもまた一つのアプリ**だからです。何ヶ月も前にセットアップを済ませたマシンでも、いつでも開いてステップの役割を確かめられます。

![ウィンドウ内の Setup アプリ：左側に 9 ステップのレール、右側に開かれた「スペシャリストを作る」ステップ](../screenshots/setup-app.png)

同じカタログ、同じプローブ、同じペイン — ターミナルの中でも同様です。SSH 越しの `bento setup` は、ブラウザが中断したまさにその地点から続きを引き継ぎます。

## 最初に尋ねられるのは、どんな仕事をするかということ

セットアップはドアではなく、問いで終わります：**仕事をひとつ、私にください。** 3 つのうちから 1 つを選び、質問に 2 つ答えれば、あなたが一つもアプリを開かないうちに、このマシンはあなたのために何かを始めています。

![Jobs 画面：3 つのレシピ — 毎朝ブリーフィングする、フォルダーを見張る、ページが変わったら知らせる — と、選んだレシピの質問、そしてそれに許可される内容が正確に表示されている](../screenshots/jobs.png)

| | |
|---|---|
| **毎朝ブリーフィングする** | あなたが追っている事柄を夜のうちに読み込み、待っている一枚のページを残します |
| **フォルダーを見張る** | *あなたが選んだ*フォルダーに何が届いたかに気づき、それが何かを見極め、あなたに伝えます |
| **ページが変わったら知らせる** | ページを確認し、本当に何かが変わったときだけ声を上げます |

やらないことが 2 つあります。あなたが見ていない権限を自分に与えることはしません：パネルはボタンを押す前に正確な権限を印字します。しかもそれを書き込むのと同じコードが計算したもので — 「`~/Downloads/*` を読む、それ以外は何も読まない」といった具合です。そして、機能しない連絡手段を提示することもしません：ペアリングされていない Telegram は、それを直す一文とともにグレーアウトで示され、決して隠されず、こっそり別のものに差し替えられることもありません。

最後のボタンは **「今すぐ実行して、動くところを見せて」** です — なぜなら、発火するところを見ていないスケジュールは約束にすぎず、新しいユーザーには、それを信じる理由がないからです。

ジョブは*フロー*であり、新種の何かではありません：同じスケジューラー、同じ権限ゲート、同じ監査台帳です。画面のないマシンでは：`bento job recipes`、続いて `bento job add morning-brief --topics "…"`。

## 三つの顔、一つのプログラム

Bento は 3 つの場所で動き、**すべての機能が 3 つすべてのために作られています**。これはあらゆる変更について最後にではなく、最初に問われる問いです。

| | それが何か | 起動方法 |
|---|---|---|
| **GUI** | macOS、Windows、Linux 上のウィンドウ（またはタブ）。追加でインストールするものは何もありません | `bento` |
| **TUI** | ターミナルの中の OS 全体 — サーバー用、あるいは SSH 越しの画面のない Pi 用 | `bento tui` |
| **SUI** | Bento が**あなたの Linux セッションそのもの**：マシンを丸ごと所有します | `bento installer` |

> コマンドは `bento` です。`agentos` も依然として動作し、これからもずっと動作します — 人々のシェル履歴、systemd ユニット、スクリプトの中に生きているものであり、私たちが選んだ改名のために、それを失わせるべきではありません。

### 一台のマシンを、複数の人で

アカウントを追加すると、各人は**それぞれ自分の家**を持ちます — 自分のデータベース、記憶、エージェント、チャネル、MCP サーバー、そして認証情報です。一つ忘れた `WHERE` 句が漏らしてしまう `user_id` カラムではありません：それぞれ自分のディレクトリです。なぜなら、二つのファイルは互いに漏れ合うことができないからです。

![Users アプリ：2 つのアカウント。Ada Lovelace は admin かつ「これがあなた」とマークされ、Bob Kahn は役割ドロップダウンが Executor に設定されている](../screenshots/users-two-accounts.png)

役割は 2 つ — **executor**（自分の家の中のすべて）と **admin**（それに加えてマシン）。設定は共有されたままなので、プロバイダーのキーは人ごとに 1 つではなく、マシンに対して 1 つです。エージェントとアプリは、共有ライブラリを通じて、意図的にコピーとして行き来します。

そしてそれは**一度のサインインで、ここでもどこからでも**：アカウントを持つマシンはそれらによってロックされるので、誰かのポケットの中の電話は、デスクトップと同じユーザー名とパスワードを使い、自分の家に着地します。考え出したり、共有したり、忘れたりする 2 つ目の共有パスフレーズはありません。

![リモートアクセスパネルには「このマシンのアカウントによってロックされています — 全員が、ここで使うのと同じユーザー名とパスワードで、自分の電話からサインインします」と書かれている](../screenshots/remote-locked-by-accounts.png)

### 何をしているかが見える

![飛行中のターン：完了した Read 呼び出しはその所要時間を保ち、実行中の Bash 呼び出しはその場で時を刻み、その下の行はどのステップで、ターンにどれだけ時間がかかったかを告げる](../screenshots/agent-working.png)

ターンはほとんどが待ち時間であり、4 分間の「作業中…」は何も教えてくれません — 思考中のモデルと、静かに死んでしまった実行は、それだけを見ると見分けがつきません。待機中のすべての面が、**何に取り組んでいて、どれだけの時間か**を告げます：実行中の呼び出しはその場で時を刻み（`running · 2m 14s`）、完了した呼び出しはその所要時間を保ち、その下の行はステップとターンの合計を担います。同じ一文がプレゼンスバブルにもオムニバーにも現れるので、チャットを開かずにデスクトップから答えを得られます。

### 自らのチームを組める — そして、その前に尋ねる

![委任を承認する：カードはエージェント、モデル、ステップと時間の予算、そしてそれが持つことになる正確なツールとスキルを名指しする](../screenshots/agent-approval.png)

既存のスペシャリストが合わないとき、エージェントは一人を**作り出し**、それに委任します。エージェントを定義しても、それには何の権限も与えられません。実際に初めて使われるそのときに、それが動くモデル、その予算、そしてその定義が与える正確なツールとスキルを名指しするカードが表示されます — なぜなら、思い描くこともできないアクターへの同意は、名ばかりの同意だからです。`researcher` を承認することは `deploy-bot` を承認することではなく、その付与は他のものと同じく Permissions で取り消せます。[仕組みを見る →](../security.md)

### 自らのマニュアルから、自らについての問いに答える

![Docs アプリが、マニュアルに根ざしてこの OS についての問いに答えている](../screenshots/docs-ask.png)

マニュアルは検索インデックスの中にあるので、「アプリのインターネット接続を止めつつ、動作は保つにはどうすればいい？」という問いは、別のプロジェクトについてのモデルの記憶からではなく、**これらのページ**から答えられます — しかも返信は、使ったページを名指しします。これは一発の参照ではなく、エージェント的な検索です：エージェントは検索し、読み、最初の一巡で見つからなければ、また検索します。

### ウィンドウらしく振る舞うウィンドウ

![デスクトップ上に重なった 4 つの Bento ウィンドウ：フォーカスされたものはアクセントのリングと完全な影を帯び、残りは後退する](../screenshots/windows.png)

ウィンドウは**あなたが残した場所**に開きます — 位置とサイズはアプリごとに記憶されます — そして初めて開くウィンドウはタイトルバー 1 本分より大きくずれてカスケードするので、下にあるものの名前がまだ読めます。フォーカスされたウィンドウはアクセントのリングと完全な影を帯び、他は後退します。タイトルバーの ✦ は、*そのアプリの中にいる*エージェントです：そこを離れずに、画面に映っているものについて尋ねられます。

### 5 つのデザイン言語、5 つのパレットではなく

![5 つの組み込みデザイン言語テーマ：Bento、Liquid Glass、Spatial、Claymorphism、Minimalism](../screenshots/themes.png)

**Bento · Liquid Glass · Spatial · Claymorphism · Minimalism。** どれもシェル全体を切り直します — サーフェス、角丸、立体感、ぼかし、書体 — そしてそれぞれ独自の壁紙を持ってきます。壁紙は SVG として同梱されます：各数 KB で、電話から 4K パネルまで鮮明です。[もっと見る →](../desktop.md#themes)

ガラスはデスクトップが描けるもののうち最も高コストで、その負荷はウィンドウを開くたびに積み重なります。**Themes → Effects** はあなたのマシンを測り、必要なときにだけそれを抑えます — Liquid Glass の 5 つのウィンドウは 6.5fps から 27（抑制）または 60（オフ）になりました。

### あなたがすでにいる場所に、届く

![Settings 内の WhatsApp チャネル：4 つの Cloud API フィールド、Meta のコンソールに貼り付けるコールバック URL、ペアリングされた番号、そして 24 時間ウィンドウが開いているかどうか](../screenshots/channels-whatsapp.png)

**Telegram と WhatsApp はネイティブチャネル**です — 机の前と同じ会話、同じ記憶、同じツール、同じ承認ボタン。通知ブリッジではありません：あなたの電話からの返信は、今朝あなたが始めたスレッドの続きになります。

WhatsApp には**2 つのトランスポート**があり、それらは正反対の方向に失敗します。Meta の Cloud API は公式ですが、開発者アカウントと公開の webhook が必要で、最後のメッセージから 24 時間を過ぎると自由形式の返信をまったく運びません — カードはそのウィンドウが開いているかを告げ、通せない送信はそのことと直し方を告げ、スケジュールされたジョブはまずレポートを保存するので何も失われません。WhatsApp Web リンクは QR スキャンだけで済み、24 時間ウィンドウがありませんが、**非公式**であり、Bento は何かをダウンロードする前にインストールカードでそう告げます。[セットアップ →](../whatsapp.md)

Telegram は**管理コンソール**でもあります：`/agents`、`/run`、`/flows`、`/model`、`/logs`、`/perms` — 所有者専用で、*何かをする*すべてのコマンドはデスクトップと同じ権限ゲートと同じ承認ボタンを通るので、決して安易な抜け道にはなりません。[コマンド →](../integrations.md)

### 単にデスクトップの上に住むのではなく、デスクトップ*そのもの*になれる

![Bento デスクトップの上にあるネイティブの Wayland アプリケーション。その上にはメニューバーが、下にはドックが予約されている](../screenshots/session-native-window.png)

ログインすれば Bento があなたの Linux セッションになります。デスクトップは**背景レイヤー上の Wayland レイヤーサーフェス**として描かれるので、ネイティブアプリケーションのウィンドウは通常のスタック順でその上に来ます — 何かが持ち上げられたり下げられたりするからではなく、それが「背景」の意味だからです。メニューバーとドックは**コンポジターに予約された**帯の中に座ります。GNOME や KDE のパネルが使うのと同じ仕組みなので、全画面アプリはそれらを飲み込むのではなく、その縁で止まります。

![Bento デスクトップの左半分と右半分にスナップされた 2 つのネイティブターミナル](../screenshots/session-snapped.png)

ネイティブアプリのための完全なウィンドウ管理：半分や四分の一へのスナップ、タイル、フロート、レイアウト、キーボードによるリサイズ、ワークスペース、最小化、そして Alt-Tab スイッチャー — タスクバーとメニューバーは、フォーカスを持つアプリを追随します。[セッション UI →](../session-ui.md)

### Bento の中から、アプリケーションをインストールする

![マシンのパッケージカタログを検索する Applications アプリ。結果ごとにインストールボタンが付いている](../screenshots/app-store.png)

ソフトウェアをインストールできないデスクトップはデモです。*Applications → Get apps…* はマシン自身のカタログ — AppStream、Flatpak、apt — を検索し、実行する前に正確なコマンドを見せます。Flatpak が存在するところではそれが優先されます。なぜなら、ユーザーごとのインストールはパスワードをまったく必要としないからです。Bento は何もミラーせず、何も同梱しません。あなたがすでに持っているパッケージマネージャーに尋ねるのです。

### あなたの本物の画面を、電話に、ブラウザの中で

![電話のブラウザで開いた Bento のリモートデスクトップ。ネイティブアプリが載ったマシンの本物の画面と、電話のキーボードに欠けているキーのツールバーが表示されている](../screenshots/phone-remote-desktop.png)

**リモートアクセス**はあなたに Bento のシェルを送ります。これは HTML であり、完璧に運ばれます — しかしネイティブアプリはマシン自身のディスプレイ上のピクセルであり、そもそもページの一部ではありませんでした。**リモートデスクトップ**がそれを埋めます：Bento は*自らの*認証された接続越しに画面を中継するので、本物のデスクトップを、クリック可能な状態で、電話にインストールする VNC アプリなしに手にできます。

その形こそが要点です — VNC サーバーは `127.0.0.1` にとどまり、決してネットワークに近づきません。それを守るのは、あなたがすでに使っているパスフレーズです。[リモートアクセス →](../remote-access.md)

## なぜ Bento Box AI なのか

- **チャットボックスではなく、本物のデスクトップ** — ドラッグ可能なウィンドウ、タスクバー、仮想デスクトップ、ウィジェット、テーマ、コマンドパレット、そして 25 以上の組み込みアプリ。
- **手を持つエージェント** — シェルコマンド、ファイル管理、Web リサーチ、デスクトップ通知、スケジュールされたジョブ、HTML レポート、そしてアプリ作成 — すべて平易な言葉から。
- **ローカルファーストでプライベート** — すべてを Ollama とともにあなたのハードウェア上で動かせます。クラウドキーを追加しない限り、何もマシンから出ていきません。localhost だけにバインドし、パスフレーズで保護された[リモートアクセス](../remote-access.md)を意図的にオンにするまでそのままです。
- **ライフサイクル全体を一つ屋根の下に** — **Train · Test · Operate · Build · Ship · Manage** が、一つの画面（Mission Control）でライブに：自分の GPU で自分のモデルをファインチューンし、あらゆる自己改変をテストで関門にかけ、スケジュールされたジョブを実行し、アプリを作り、GitHub に出荷します。
- **自己拡張** — エージェントは自分のために新しい UI アプリを作り（App Studio）、スキルと MCP ツールサーバーをインストールし、Bento 自身のソースコードを改変できます（自動スナップショットと、再起動の前に通らねばならないテストスイート付き）。
- **積み重なる記憶** — 二層の記憶、ライブのナレッジグラフ、そして永続する「魂」。すべての会話の後に自動的に学ばれます。
- **設計からして安全** — 自律レベル、承認プロンプト、許可/拒否ポリシー、bubblewrap によるフォルダーサンドボックス、ハードブロックされた破壊的コマンド、そしてワンクリックの復元ポイント。

## クイックスタート

**macOS または Linux で、コマンド一つ。** それはすべてをインストールし — `uv` 経由の Python を含めて — Bento を起動し、それから「完了」と言う前に、動いているサーバーに問いを投げて*動作を証明*します。

```bash
curl -fsSL https://raw.githubusercontent.com/contact9prime-lab/bento-ai-os/master/install.sh | sh
```

その後 **http://127.0.0.1:8321** を開くか、ターミナルで同じ 9 ステップを行う `bento setup` を実行してください。

尋ねられる端末があれば、インストーラーは終わる前に二つのことを尋ねます。このマシンを他のデバイスから
到達可能にするか、そしてそうするなら、**パスフレーズ**と**アカウント**のどちらでサインインするか。
画面のないマシンでは、最初の問いこそが「見に行けるインストール」と「見に行けないインストール」の分かれ目です。
`--yes` はこれには意図的に答えません — ここで開いたポートは、開いたシェルだからです。

それはあなたの `PATH` に `bento` コマンドを残します（`~/.local/bin` に。そこに無ければあなたのシェルプロファイルに追加されます — その後は新しいターミナルを開いてください）。 `bento --help` は新しいマシンに必要な 10 個のコマンドを表示します。残りは `bento help --all` です。

### 選んだアドレスとポートにインストールする

SSH 越しに届くサーバーでは、`127.0.0.1:8321` は「何からも届かない」を意味します。インストーラーにパスフレーズとアドレスを渡せば、起動サービスがすでに正しいポートを向いた状態で、準備万端で立ち上がります：

```bash
curl -fsSL https://raw.githubusercontent.com/contact9prime-lab/bento-ai-os/master/install.sh \
  | sh -s -- --passphrase='something long and unguessable' --bind=0.0.0.0 --port=8080
```

そのマシンは今や**すべての**インターフェースのポート 8080 で応答し、何かをする前にそのパスフレーズを求めます。`127.0.0.1:8080` 経由のローカル利用は変わりません。

インストーラーは、2 つのうちどちらの状態を残したかを告げます — `AgentOS is running` は、本当に何かが待ち受けているときにだけ表示されます。手近にサービスマネージャーの無いマシン（コンテナ、systemd でないディストロ、ユーザー D-Bus の無い SSH）では、代わりにそう告げ、`bento service start` が仕事を仕上げます。

すべてではなく一つのインターフェースだけ — プライベート VLAN、Tailscale アドレス：

```bash
curl -fsSL https://raw.githubusercontent.com/contact9prime-lab/bento-ai-os/master/install.sh \
  | sh -s -- --passphrase='something long and unguessable' --bind=192.168.1.20 --port=8080
```

ポートだけ変えて、ループバック専用のまま：

```bash
curl -fsSL https://raw.githubusercontent.com/contact9prime-lab/bento-ai-os/master/install.sh \
  | sh -s -- --port=8080
```

> **`-s --` は省略できません。** `curl … | sh --port=8080` はそのフラグを `sh` に渡してしまい、`sh` はそれを拒否します — パイプされたスクリプトは、自分自身の引数を受け取りません。`-s --` は「これ以降はスクリプトのためのもの」を意味します。これはこれらのフラグが失われる最もよくある形であり、エラーが `sh` を名指しするので、壊れたインストーラーのように読めてしまいます。

**すべてのフラグ：**

| フラグ | 何をするか |
|---|---|
| `--passphrase=SECRET` | サインインにこれを必須とし、ループバック以外へのバインドを許す — ここで渡せばインストーラーは尋ねません |
| `--bind=ADDR` | どのインターフェースで待ち受けるか（既定 `0.0.0.0`）。`--passphrase` が必要 |
| `--port=N` | どのポートか（既定 `8321`）。設定に保存されるので起動サービスがそれを使う |
| `--yes` | 任意コンポーネントすべてに yes と答える — ポートを開くことには**答えません** |
| `--no-service` | ランチャーも起動サービスも無し（コンテナ、CI） |
| `--no-verify` | 「動作を証明する」ステップを飛ばす |

### 後から変更する

上記のすべては **`~/.agentos/config.json`**（あるいは `$AGENTOS_HOME` の下）に生きており、`bento config` はあなたがそれを探し出さなくても読み書きします：

```bash
bento config                       # ファイル全体、シークレットはマスクされる
bento config port                  # 一つの設定
bento config port 8080             # それを変える
bento config remote.bind 0.0.0.0   # 入れ子の設定にはドット区切りのパス
bento config --path                # ファイルの場所
bento config --edit                # $EDITOR で開く — 不正な JSON の保存は拒否する
```

`bento remote` は同じ設定で、到達性に関するものをまとめたものです：

```bash
bento remote --on --passphrase 'something long' --bind 0.0.0.0   # 共有する一つの秘密
bento user add alice && bento remote --on --bind 0.0.0.0          # または一人ずつのアカウント
bento remote --port 8080                                          # ポート
bento remote                                                      # 今どうなっているか、そして誰がサインインするか
```

**ポートの変更は、それ自体ではインストール済みの起動サービスに届きません** — systemd ユニットと LaunchAgent はそれを `ExecStart` に焼き込みます。どちらのコマンドも、それが当てはまるときに知らせます：

```bash
bento service install && bento service restart
```

> **他のマシンから届くことは、既定ではなく意図的な選択です。** Bento は錠がかかるまで、つまりパスフレーズか、誰かがサインインするアカウントができるまで、`127.0.0.1` だけで待ち受けます。エージェントは本物のシェルを持つので — ここで開かれたポートは、開かれたシェルです。そのため `--bind` 単独は拒否され、リモートアクセスがオフのままの `bento serve --host 0.0.0.0` も同様です。 二つの錠は重ねるものではなく、どちらか一方です。アカウントが存在すればそれ自体が錠であり、その手前のパスフレーズは何も読まない設定にすぎません。

**1024 未満のポートについて。** Linux では非 root プロセスに対して拒否され、macOS では拒否はアドレスごとです — `0.0.0.0:80` を許し `127.0.0.1:80` を拒否します。だからここでは番号から推測するものは何もありません：`--port` は実際のバインドを試み、カーネルが no と言えば、それを直す `sysctl` の一行、リダイレクトルール、あるいはプロキシの選択肢を印字します。Linux では、ポート 80 はたいてい一つのコマンドを意味します：

```bash
echo 'net.ipv4.ip_unprivileged_port_start=80' | sudo tee /etc/sysctl.d/50-agentos.conf
sudo sysctl --system
```

サーバーを root として動かすことは推奨されません — エージェントは本物のシェルを持っています。

## Linux デスクトップとして動かす（SUI）

```bash
uv run bento installer      # あなたのディストロを検出し、足りないものをインストールし、ログイン画面に追加する
```

その後ログアウトし、ログイン画面で **Bento Box AI** を選んでください。あなたの既存のデスクトップは手つかずです — 戻すのは、ログアウトしてもう一度 Ubuntu を選ぶだけです。

インストーラーはディストリビューションを検出し、欲しいパッケージすべてとその理由を名指しし、何かをインストールする前に尋ねます。2 つのグループ：コンポジターエンジン（sway とその仲間、MIT）と、ネイティブデスクトップサーフェス（`python3-gi`、`python3-gi-cairo`、gtk-layer-shell、WebKitGTK）。後者は、デスクトップをブラウザウィンドウではなく本物の Wayland サーフェスにします。

**Bento はそれらのいずれも同梱も再配布もしません。** gtk-layer-shell は MIT ですが、GTK、PyGObject、WebKitGTK は LGPL であり、このプロジェクトが*依存する*ものは寛容なライセンスのままに保たれます — だからそれらは、ライセンスを目の前に置いた上で求められます。それらが無くてもセッションは動作し、デスクトップを Chromium ウィンドウの中に描きます。
[ライセンス →](../licensing.md) · [セッション UI →](../session-ui.md)

デスクトップについて何か不調があれば、一つのコマンドが理由を告げます：

```bash
uv run bento doctor --session   # このマシンで実際に何が描けるかを調べ、それを告げる
```

それはインタープリター、GTK のディスプレイ、コンポジターのレイヤーシェル対応、そして WebKit が描画*でき、描画し続けられる*かどうかを — ウィンドウの中でも、レイヤーサーフェス上でも — 確かめ、それから判定を下します。プローブはサブプロセスの中で走ります。なぜなら、それが探す失敗はアボートやセグフォルトであり、doctor をクラッシュさせるプローブは、自らがクラッシュしたことを報告できないからです。

## Debian/Ubuntu パッケージ（.deb）としてインストール

自己完結型の `.deb`（アプリ**と**全依存関係を含む Python venv を同梱 — インストール時にネットワーク不要）：

```bash
./packaging/build-deb.sh                                   # → packaging/dist/agentos_<ver>_<arch>.deb
sudo dpkg -i packaging/dist/agentos_0.1.0_amd64.deb        # /opt/agentos + ランチャー + サービスにインストール
systemctl --user enable --now agentos                      # ログイン時に開始（ユーザーごと）
bento app                                                  # またはメニューから起動
```

`apt`/`dpkg` が更新と削除を処理します。それは `bubblewrap`（サンドボックス）と `xdg-utils` を **Recommends** し、`ollama`、`nodejs`、`git` を **Suggests** します。デスクトップパッケージはさらに、セッション UI スタックと `wayvnc`/`novnc` を **Suggests** します — 依存ではなく提案なのは、apt が既定で Recommends をインストールするので、それでは同梱を柔らかい名前で呼んでいるだけになるからです。

## 本物のアプリとしてインストール（起動時に自動開始）— ソースから

```bash
uv run bento install      # アプリランチャー + ログイン/起動時に開始するバックグラウンドサービス
```

正しいネイティブの仕組みが自動的に使われます：Linux では `.desktop` ランチャーと **systemd ユーザーサービス**（linger 付きで、起動時に開始）、macOS ではアプリバンドルと **LaunchAgents**、Windows ではスタートメニューのショートカットと **Startup エントリ**。

一組のコマンドが 3 つすべてを操ります — このマシンが systemd を使うか launchd を使うかを、自分のエージェントを制御するために知る必要はないはずです：

```bash
bento service status       # 動いているか、起動時に戻ってくるか、ポートは応答しているか
bento service start        # …stop、restart
bento service logs -f      # journalctl か、ログファイルか、このマシンが使う方
bento service uninstall    # バックグラウンドサービスだけを削除 — ランチャーとデータは残る
bento uninstall            # ランチャー + サービスを削除（あなたのデータは残る）
bento app                  # いつでもクロームレスのデスクトップウィンドウとして開く
```

`bento service status` はスーパーバイザーが信じていること**と**ポートが応答するかどうかを、別々に報告します：何も待ち受けていないのに「active」なユニットはクラッシュループであり、それこそが見えるようにしておく価値のある状態です。

## デスクトップ

- **ウィンドウ** — すべてのアプリは、最小化/最大化/クローズと z 順序を備えた、ドラッグ可能でリサイズ可能なウィンドウで開きます。**タスクバー**が開いているウィンドウを追い、**スタートメニュー**がすべてを起動します。
- **眠るウィンドウ** — 見えないウィンドウは周期的な仕事をやめ、戻ってきた瞬間に更新します。6 つのアプリを開いてすべて最小化した場合、10 秒あたり 25 リクエストから 2 になりました。
- **仮想デスクトップ** — タスクバーのページャー。`Ctrl+1..6` で切り替え、右クリックでウィンドウをそこへ移動。ウィジェットはデスクトップごとなので、それぞれが独自の空間です。
- **ウィジェット** — 任意のアプリを枠なしのライブタイルとしてピン留め。ドラッグ、リサイズでき、起動時に復元されます。
- **コマンドパレット** — `Ctrl+Space`（または `Ctrl+K`）で、任意のアプリやアクションのあいまい起動、あるいは「Ask Aria …」でエージェントに直送。`Ctrl+Alt+T` はターミナルを開きます。
- **ルック＆フィール** — ローカルギャラリー付きの AI 生成壁紙、エージェントが働く間の思考アニメーション、そして任意の音声。視覚対応モデルのために、画像をチャットに直接貼り付けられます。

| **Logs** | システムが行ったすべて（ターン、ツール、MCP、telegram、ジョブ） |
| **Scheduler** | 繰り返しのバックグラウンド**ジョブ** |
| **Snapshots** | OS 全体の復元ポイント（設定、データ、ソース） |
| **Settings** | プロバイダー、モデル、自律性、音声、サンドボックス、エージェント名 |

## エージェントにできること

エージェント（既定の名前は **Aria**）は大きなツールセットを持ち、チャットや Telegram から OS 全体を動かせます：

- **マシンに対して行動する** — シェルコマンドの実行、ファイルの読み書き、Web の取得、ホスト上でのアプリ/ファイルのオープン、デスクトップ通知。
- **結果を届ける** — `save_report` はスタイル付きの HTML レポートを書き、それは Files に表示され、あなたのブラウザで開き、要約を Telegram へ送ることもできます。エージェントは**仕事を仕上げる**よう指示されています — リサーチを実際の成果物に変え、検索の後で止まらないように。
- **OS を作る** — `create_app` はデスクトップアイコン付きの新しい UI アプリを作り、`pin_widget` はそれらをデスクトップに置き、`add_mcp_server` は新しいツールチャネルを接続します。
- **育つ** — 二層の記憶、ナレッジグラフ、`update_soul` — 加えて**自動学習**：毎ターンの後のバックグラウンドの一巡が、記憶と事実を自力で抽出します。
- **自動化する** — `schedule_task` は、レポートおよび/または Telegram に届ける画面なしの**ジョブ**を作ります。
- **自己を拡張する** — `read_source` / `develop_agentos` は、Bento 自身の**ソースコード**を改変させます。先に自動スナップショットを取り、書き込む前に構文チェックします。

平易な言葉で頼んでください：*「github の MCP チャネルを追加して」「習慣トラッカーを作ってデスクトップ 2 にピン留めして」「毎朝ソーシャルメディアのトレンドを私の Telegram に報告して」「inkscape をインストールして」。*

## モデルとプロバイダー

- **Ollama**（ローカル） — 自動発見。何もマシンから出ていきません。
- **Anthropic**、**OpenAI**、**OpenRouter**、あるいは任意の **OpenAI 互換**エンドポイント（LM Studio、vLLM、Groq、…）。
- **画像生成** — キーが設定されていれば Google Gemini または OpenAI の画像モデル、そうでなければ無料のフォールバック。

`ANTHROPIC_API_KEY`、`OPENAI_API_KEY`、`OPENROUTER_API_KEY`、`GOOGLE_API_KEY` は自動的に拾われます。チャットウィンドウのドロップダウンから、途中でモデルを切り替えられます。

## 安全性

- **自律レベル** — Paranoid / Balanced は読み取り専用のアクションを自動実行し、システムを変更するものの前には尋ねます。Full はすべてを実行します。破壊的コマンドは、どのレベルでも**ハードブロック**されます。
- **ポリシー** — 常時許可/常時拒否ルール（`*` ワイルドカード付き）を `<tool> <command>` に照合します。
- **フォルダーサンドボックス** — bubblewrap があれば、エージェントのシェル/ファイルツールとターミナルは一つのフォルダーに閉じ込められ、ファイルシステムの残りは読み取り専用になります。
- **スナップショット** — 復元ポイント。エージェントは自分のコードを編集する前に自動スナップショットを取ります。
- **既定でプライベート** — `127.0.0.1` にバインドします。リモートアクセスは、あなたがパスフレーズでオンにするまでオフであり、ソフトウェアのインストールはマシン自身以外のどこからも拒否されます。

## Telegram · MCP · プログラム可能

**Telegram** — @BotFather にメッセージを送り、トークンを Telegram アプリに貼り付ければ、最初のプライベートチャットが所有者になります。エージェントはそこで全ツールを持ち、リスクのあるアクションはインラインの Allow/Deny ボタンを送ります。

**MCP サーバー** — カタログから外部ツールサーバー（Playwright、filesystem、fetch、git、GitHub、Postgres、Slack、search、…）、あるいはカスタムの `stdio`/`http` サーバーを追加します。それらのツールはエージェントには `mcp_<server>_<tool>` として、作られたアプリには `POST /api/tool` 経由で見えます。

**プログラム可能** — 一発の実行には `bento ask "…"`。REST API（`POST /api/chat`、`GET /api/system`、`POST /api/tool`、…）。`/ws`（ストリーミングチャット + 承認）と `/ws/terminal`（ホスト PTY）の WebSocket。あなたが作るアプリは同一オリジンの iframe の中で動き、そのすべてを呼べます。

## アーキテクチャ

```
agentos/                 # Python パッケージは元の名前を保つ。下記「名前について」を参照
├── __main__.py    # CLI エントリ：serve · app · installer · doctor · apps · remote-desktop · ask
├── agent.py       # カーネル：plan → act（tools）→ observe ループ、承認ゲート、ペルソナ
├── providers.py   # 統一ストリーミングチャット：Ollama / Anthropic / OpenAI / OpenRouter / カスタム
├── tools.py       # 手：シェル、ファイル、Web、アプリ、レポート、memory、KG、soul、スキル、MCP
├── shellhost.py   # SUI：wlr-layer-shell サーフェスとしてのデスクトップ（GTK + WebKitGTK）
├── sessiondoctor.py # このマシンで実際に何がデスクトップを描けるか
├── compositor.py  # sway/wlroots IPC：ウィンドウ、ワークスペース、出力、ライブイベント
├── appstore.py    # appstream / flatpak / apt によるネイティブアプリケーションのインストール
├── remotedesktop.py # ブラウザのリモートデスクトップ、認証された接続越しに中継
├── installer.py   # OS を意識したセットアップ：ディストロを検出し、足りないものを入れ、先に尋ねる
├── memory.py      # SQLite：会話、記憶、タスク、ログ、KG、スキル、アプリ
├── server.py      # FastAPI：デスクトップ UI、REST API、WebSocket ストリーム、ファイル配信
└── ui/
    ├── src/       # デスクトップのソース — ここを編集する
    └── index.html # `python -m agentos.ui.build` で生成される（編集しない）
```
