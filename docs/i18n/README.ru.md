**Ваш компьютер, но с мозгом.** Bento Box AI — это самостоятельно размещаемая **среда AI-рабочего
стола**: полноценный рабочий стол — окна, приложения, файлы, терминал — управляемый **автономным
AI-агентом**, который совершает **реальные действия** на вашем компьютере. Используйте локальные
модели через [Ollama](https://ollama.com) для полной приватности или облачные модели (Anthropic
Claude, OpenAI, OpenRouter или любой совместимый с OpenAI эндпоинт) — всегда с вашего согласия.
Агент умеет искать в интернете, создавать собственные приложения, планировать задачи, запоминать
то, что узнаёт, дополнять свой собственный исходный код и связываться с вами через Telegram или
WhatsApp.

![Python 3.10+](https://img.shields.io/badge/python-3.10%2B-blue)
![Platforms](https://img.shields.io/badge/platform-Linux%20·%20macOS%20·%20Windows-lightgrey)

Работает по адресу `http://127.0.0.1:8321` — приватно по умолчанию, устанавливается как служба,
запускаемая при загрузке.

```bash

```

**Полная документация находится в [`docs/`](../README.md)** — установка, руководство пользователя

## Настройка состоит из девяти шагов, и каждый оставляет что-то после себя

Это не форма настроек с полосой прогресса. Каждый шаг **создаёт что-то реальное** — модель,
которая отвечает, агента, который существует, поток, который выполняется, расписание, которое
срабатывает — и говорит, что вы в итоге получите, прежде чем что-либо у вас спросить.

![Экран первого запуска настройки: слева рейка из девяти шагов, а справа «Дайте имя вашему агенту» с надписью «В итоге вы получите: имя в строке меню и в каждом ответе»](../screenshots/onboarding-1-name.png)

Каждый шаг **проверяется, а не запоминается**: он отмечен потому, что на машине есть эта вещь.
Удалите агента — и шаг вернётся в статус «сделать». Именно это делает безопасным повторный запуск —
а повторный запуск здесь нормальное дело, потому что **Настройка — это тоже приложение**. Откройте
её в любой момент, чтобы посмотреть, что делает шаг, на машине, которую вы настроили месяцы назад.

![Приложение «Настройка» в окне: слева рейка из девяти шагов, справа открыт шаг «Создать специалиста»](../screenshots/setup-app.png)

Тот же каталог, та же проверка, те же панели — в том числе в терминале, где `bento setup` по
SSH продолжает ровно с того места, где остановился браузер.

## Первое, о чём она вас спрашивает, — какую задачу выполнить

Настройка заканчивается вопросом, а не дверью: **дайте мне задачу.** Выберите одну из трёх,
ответьте на два вопроса — и эта машина уже делает что-то для вас ещё до того, как вы открыли хоть
одно приложение.

![Экран «Задачи»: три рецепта — брифинг каждое утро, слежение за папкой, оповещение об изменении страницы — с вопросами выбранного рецепта и точным описанием того, что ему будет разрешено делать](../screenshots/jobs.png)

| | |
|---|---|
| **Брифинг каждое утро** | за ночь изучает то, за чем вы следите, и оставляет одну страницу ожидать вас |
| **Следить за папкой** | замечает, что попадает в *выбранную вами* папку, разбирается, что это, и сообщает вам |
| **Сообщить, когда страница изменится** | проверяет страницу и подаёт голос, только когда что-то действительно изменилось |

Две вещи, которых она делать не станет. Она не выдаст себе ничего, чего вы не видели: панель
выводит точные разрешения прежде, чем вы нажмёте кнопку, вычисленные тем же кодом, который их
записывает — «читает `~/Downloads/*`, и ничего больше». И она не предложит способ связи с вами,
который не работает: непривязанный Telegram показан затенённым с фразой, которая это исправит,
никогда не спрятан и никогда не подменён втихую.

Последняя кнопка — **«Запустить прямо сейчас, чтобы я увидел, как это работает»** — потому что
расписание, срабатывания которого вы не видели, — это обещание, а у нового пользователя нет причин
в него верить.

Задача — это *поток*, а не новый вид сущности: тот же планировщик, тот же контроль разрешений, тот
же журнал аудита. На машине без графики: `bento job recipes`, затем
`bento job add morning-brief --topics "…"`.

## Три лица, одна программа

Bento работает в трёх местах, и **каждая функция создаётся для всех трёх**. Это первый вопрос,
задаваемый любому изменению, а не последний.

| | Что это | Как запустить |
|---|---|---|
| **GUI** | окно (или вкладка) на macOS, Windows или Linux. Ничего дополнительно устанавливать не нужно | `bento` |
| **TUI** | вся ОС в терминале — для сервера или для Raspberry Pi без экрана по SSH | `bento tui` |
| **SUI** | Bento **является** вашей Linux-сессией: он владеет машиной | `bento installer` |

> Команда — `bento`. `agentos` по-прежнему работает и всегда будет — она в истории команд у людей,
> в юнитах systemd и в скриптах, и переименование, которое выбрали мы, не должно стоить им этого.

### Несколько человек, одна машина

Добавьте учётную запись — и каждый человек получает **свой собственный дом**: свою базу данных,
память, агентов, каналы, MCP-серверы и учётные данные. Не столбец `user_id`, который одна забытая
конструкция `WHERE` протекает: свой собственный каталог, потому что два файла не могут протечь друг
в друга.

![Приложение «Пользователи»: две учётные записи, Ада Лавлейс отмечена как администратор и «это вы», Боб Кан с выпадающим списком роли, установленным на «Исполнитель»](../screenshots/users-two-accounts.png)

Две роли — **исполнитель** (всё внутри своего дома) и **администратор** (то же самое, плюс
машина). Настройки остаются общими, так что для машины есть один ключ провайдера, а не по одному
на человека. Агенты и приложения переходят намеренно, в виде копий, через общую библиотеку.

И это **один вход, здесь и откуда угодно**: машина с учётными записями заперта ими, так что телефон
в чьём-то кармане использует те же имя пользователя и пароль, что и рабочий стол, и попадает в свой
собственный дом. Не нужно выдумывать, передавать или забывать второй общий пароль.

![Панель удалённого доступа с надписью «Заперто учётными записями этой машины — каждый входит с телефона тем же именем пользователя и паролем, что и здесь»](../screenshots/remote-locked-by-accounts.png)

### Вы можете видеть, что она делает

![Ход разговора в полёте: завершённый вызов Read сохранил свою длительность, выполняющийся вызов Bash стареет на месте, а строка ниже сообщает, на каком шаге и сколько времени занял ход](../screenshots/agent-working.png)

Ход разговора — это в основном ожидание, и «работаю…» в течение четырёх минут не говорит вам
ничего — думающая модель и тихо умерший запуск под ним выглядят одинаково. Каждая ожидающая
поверхность сообщает, **на чём она и как долго**: выполняющийся вызов стареет на месте
(`running · 2m 14s`), завершённые вызовы сохраняют свою длительность, а строка ниже несёт шаг и
общее время хода. Та же фраза появляется на пузыре присутствия и в омнибаре, так что на неё можно
ответить с рабочего стола, не открывая чат.

### Она может собрать собственную команду — и спрашивает, прежде чем это сделать

![Подтверждение делегирования: карточка называет агента, модель, шаг и бюджет времени, а также точные инструменты и навыки, которыми он будет владеть](../screenshots/agent-approval.png)

Когда ни один существующий специалист не подходит, агент **создаёт одного** и делегирует ему.
Определение агента не даёт ему ничего; в первый раз, когда он действительно используется, вы
получаете карточку, называющую модель, на которой он работает, его бюджет и точные инструменты и
навыки, которые даёт ему его определение — потому что согласие на действующее лицо, которое вы не
можете себе представить, — это согласие только на словах. Одобрить `researcher` — это не одобрить
`deploy-bot`, и разрешение отзывается в «Разрешениях», как и любое другое.
[Как это работает →](../security.md)

### Она отвечает на вопросы о себе из собственного руководства

![Приложение «Документация» отвечает на вопрос об этой ОС, опираясь на руководство](../screenshots/docs-ask.png)

Руководство находится в индексе поиска, так что «как остановить приложению доступ в интернет, но
оставить его рабочим?» отвечается из **этих страниц**, а не из памяти модели о другом проекте — и
ответ называет использованную страницу. Это агентный поиск, а не одноразовый запрос: агент ищет,
читает и ищет снова, когда первый проход промахнулся.

### Окна, которые ведут себя как окна

![Четыре окна Bento, наложенные на рабочий стол: у активного акцентное кольцо и полная тень, остальные отступают](../screenshots/windows.png)

Окно открывается **там, где вы его оставили** — положение и размер запоминаются для каждого
приложения — а окно, открывающееся впервые, каскадируется больше чем на строку заголовка, так что
то, что под ним, по-прежнему читаемо. Активное окно несёт акцентное кольцо и полную тень; остальные
отступают. Значок ✦ в строке заголовка — это агент *внутри этого приложения*: спросите его о том,
что на экране, не покидая его.

### Пять языков дизайна, а не пять палитр

![Пять встроенных тем-языков дизайна: Bento, Liquid Glass, Spatial, Claymorphism, Minimalism](../screenshots/themes.png)

**Bento · Liquid Glass · Spatial · Claymorphism · Minimalism.** Каждый заново кроит всю оболочку —
поверхности, скругления, возвышение, размытие, шрифт — и приносит свои обои. Обои поставляются как
SVG: по несколько КБ каждый, чёткие от телефона до 4K-панели. [Подробнее →](../desktop.md#themes)

Стекло — самое дорогое, что может отрисовать рабочий стол, и стоимость нарастает с каждым открытым
окном. **Темы → Эффекты** измеряет вашу машину и снижает его только при необходимости — пять окон
в Liquid Glass прошли путь от 6,5 fps до 27 (уменьшенный) или 60 (выключенный).

### Она связывается с вами там, где вы уже есть

![Канал WhatsApp в настройках: четыре поля Cloud API, callback-URL для вставки в консоль Meta, привязанный номер и то, открыто ли 24-часовое окно](../screenshots/channels-whatsapp.png)

**Telegram и WhatsApp — это родные каналы** — тот же разговор, та же память, те же инструменты и те
же кнопки подтверждения, что и за столом. Не мост уведомлений: ответ с вашего телефона продолжает
цепочку, которую вы начали сегодня утром.

У WhatsApp есть **два транспорта**, и они отказывают в противоположных направлениях. Cloud API от
Meta официален, но требует учётной записи разработчика и публичного вебхука, и вне 24 часов с
момента вашего последнего сообщения он вообще не понесёт свободный ответ — карточка сообщает,
открыто ли это окно, отправка, которая не может пройти, говорит об этом и как это исправить, а
запланированная задача сначала сохраняет свой отчёт, так что ничего не теряется. Связь через
WhatsApp Web требует только сканирования QR-кода и не имеет 24-часового окна, но она
**неофициальна**, и Bento говорит об этом на карточке установки, прежде чем что-либо загрузится.
[Настройка →](../whatsapp.md)

Telegram — это также **консоль администратора**: `/agents`, `/run`, `/flows`, `/model`, `/logs`,
`/perms` — только для владельца, и каждая команда, которая *что-то делает*, проходит через тот же
контроль разрешений и те же кнопки подтверждения, что и рабочий стол, так что это никогда не более
дешёвый путь внутрь. [Команды →](../integrations.md)

### Один рабочий стол, любой экран

![Bento Box AI на телефоне: экран блокировки, рабочий стол, разложенный под телефон, и приложение как полноэкранный лист](../screenshots/mobile.png)

Телефон, планшет, рабочая станция — тот же рабочий стол, адаптирующийся. Окна становятся
полноэкранными листами, док растягивается вдоль нижнего края, всплывающие окна становятся листами.
Включите **Удалённый доступ** и достучитесь до него с телефона по своей сети, за паролем;
*Добавить на главный экран* делает его полноэкранным приложением.

### Она может *быть* рабочим столом, а не просто жить на одном

![Родное приложение Wayland поверх рабочего стола Bento, с зарезервированной над ним строкой меню и зарезервированным под ним доком](../screenshots/session-native-window.png)

Войдите в систему и получите Bento как свою Linux-сессию. Рабочий стол отрисовывается как
**поверхность слоя Wayland на фоновом слое**, так что окна родных приложений находятся над ним в
обычном порядке наложения — не потому, что что-то поднимается или опускается, а потому, что именно
это и значит «фон». Строка меню и док находятся в полосах, **зарезервированных с композитором**, тем
же механизмом, что использует панель GNOME или KDE, так что полноэкранное приложение останавливается
на их краях, а не поглощает их.

![Два родных терминала, привязанных к левой и правой половинам рабочего стола Bento](../screenshots/session-snapped.png)

Полное управление окнами для родных приложений: привязка к половинам и четвертям, тайлинг, парение,
раскладки, изменение размера с клавиатуры, рабочие пространства, сворачивание и переключатель
Alt-Tab — с панелью задач и строкой меню, отслеживающими то приложение, которое в фокусе.
[Интерфейс сессии →](../session-ui.md)

### Установка приложений, изнутри Bento

![Приложение «Приложения» ищет в каталоге пакетов машины, с кнопками установки для каждого результата](../screenshots/app-store.png)

Рабочий стол, на который вы не можете установить программное обеспечение, — это демо.
*Приложения → Получить приложения…* ищет в собственном каталоге машины — AppStream, Flatpak или apt —
и показывает вам точную команду перед её запуском. Flatpak предпочтителен там, где он есть, потому что
установка для одного пользователя вообще не требует пароля. Bento ничего не зеркалирует и ничего не
поставляет в комплекте; он спрашивает у менеджера пакетов, который у вас уже есть.

### Ваш настоящий экран, на вашем телефоне, в браузере

![Удалённый рабочий стол Bento, открытый в браузере телефона, показывает настоящий экран машины с родным приложением на нём и панель клавиш, которых не хватает клавиатуре телефона](../screenshots/phone-remote-desktop.png)

**Удалённый доступ** отправляет вам оболочку Bento, которая является HTML и путешествует идеально —
но родное приложение — это пиксели на собственном дисплее машины и никогда не было частью страницы.
**Удалённый рабочий стол** закрывает это: Bento ретранслирует экран по *своему собственному*
аутентифицированному соединению, так что вы получаете настоящий рабочий стол, кликабельный, без
VNC-приложения, которое нужно устанавливать на телефон.

Смысл в форме — VNC-сервер остаётся на `127.0.0.1` и никогда не приближается к сети; защищает его
пароль, который вы уже используете. [Удалённый доступ →](../remote-access.md)

### Автоматизации и горячие углы

![Приложение «Автоматизации» с сохранёнными рутинами, картой горячих углов и конструктором шагов](../screenshots/automations.png)

Назовите последовательность один раз — открыть эти приложения, сменить тему, запустить этот Python,
вызвать тот MCP-инструмент, поставить агенту задачу — и запускайте её всегда после этого из строки

- **Безопасность по замыслу** — уровни автономии, запросы на подтверждение, политики

### Установка на выбранный адрес и порт

На сервере, к которому вы обращаетесь по SSH, `127.0.0.1:8321` означает «недостижимо ни для чего».
Дайте установщику пароль и адрес — и он поднимется готовым, с загрузочной службой, уже нацеленной на
нужный порт:

```bash
curl -fsSL https://raw.githubusercontent.com/contact9prime-lab/bento-ai-os/master/install.sh \
  | sh -s -- --passphrase='something long and unguessable' --bind=0.0.0.0 --port=8080
```

Эта машина теперь отвечает на **каждом** интерфейсе на порту 8080 и запрашивает этот пароль, прежде
чем что-либо сделать. Локальное использование через `127.0.0.1:8080` не меняется.

Установщик сообщает, с каким из двух вариантов он вас оставил — `AgentOS is running` только когда
что-то действительно слушает. На машине без доступного менеджера служб (контейнер, дистрибутив без
systemd, SSH без пользовательского D-Bus) он говорит об этом вместо этого, и
`bento service start` завершает работу.

Один интерфейс, а не все — приватный VLAN, адрес Tailscale:

```bash
curl -fsSL https://raw.githubusercontent.com/contact9prime-lab/bento-ai-os/master/install.sh \
  | sh -s -- --passphrase='something long and unguessable' --bind=192.168.1.20 --port=8080
```

Просто другой порт, по-прежнему только loopback:

```bash
curl -fsSL https://raw.githubusercontent.com/contact9prime-lab/bento-ai-os/master/install.sh \
  | sh -s -- --port=8080
```

> **`-s --` не является необязательным.** `curl … | sh --port=8080` передаёт флаг в `sh`, который его
> отвергает — переданному по конвейеру скрипту не достаётся собственных аргументов. `-s --` означает
> «остальное — для скрипта». Это самый частый способ потерять эти флаги, и ошибка называет `sh`, так
> что она читается как сломанный установщик.

**Все флаги:**

| флаг | что он делает |
|---|---|
| `--passphrase=SECRET` | требовать это для входа и разрешить привязку вне loopback — если задан здесь, установщик не спрашивает |
| `--bind=ADDR` | на каком интерфейсе слушать (по умолчанию `0.0.0.0`); требует `--passphrase` |
| `--port=N` | какой порт (по умолчанию `8321`); сохраняется в конфиг, так что загрузочная служба использует его |
| `--yes` | отвечать «да» на каждый необязательный компонент — но **не** на открытие порта |
| `--no-service` | без лаунчера и без загрузочной службы (контейнеры, CI) |
| `--no-verify` | пропустить шаг «доказать, что это работает» |

### Изменение этого впоследствии

Всё вышеперечисленное живёт в **`~/.agentos/config.json`** (или под `$AGENTOS_HOME`), и
`bento config` читает и пишет его без необходимости искать файл:

```bash
bento config                       # весь файл, секреты замаскированы
bento config port                  # одна настройка
bento config port 8080             # изменить её
bento config remote.bind 0.0.0.0   # точечные пути для вложенных настроек
bento config --path                # где файл
bento config --edit                # открыть в $EDITOR — отказывается сохранять невалидный JSON
```

`bento remote` — это те же настройки, но с сгруппированными вместе теми, что касаются достижимости:

```bash
bento remote --on --passphrase 'something long' --bind 0.0.0.0   # один общий секрет
bento user add alice && bento remote --on --bind 0.0.0.0          # или по учётной записи каждому
bento remote --port 8080                                          # порт
bento remote                                                      # что сейчас и кто входит
```

**Изменение порта само по себе не доходит до установленной загрузочной службы** — юнит systemd и
LaunchAgent запекают его в `ExecStart`. Обе команды сообщают вам, когда это применимо:

```bash
bento service install && bento service restart
```

> **Достижимость с других машин — это намеренный выбор, а не значение по умолчанию.** Bento слушает
> только на `127.0.0.1`, пока у него не появится замок — пароль или учётная запись, под которой кто-то
> входит, — потому что у агента есть настоящая оболочка:
> открытый порт здесь — это открытая оболочка. `--bind` сам по себе отвергается по этой причине, как
> и `bento serve --host 0.0.0.0` с выключенным удалённым доступом. Два замка — это альтернативы, а не слои: как только появляется учётная запись, замком становится именно она, а пароль перед ней — настройка, которую ничто не читает.

**О портах ниже 1024.** Они отвергаются для непривилегированного процесса в Linux, а на macOS отказ
идёт по адресам — он предоставляет `0.0.0.0:80` и отказывает `127.0.0.1:80`. Так что ничто здесь не
гадает по номеру: `--port` пытается выполнить реальную привязку и, если ядро говорит нет, печатает
строку `sysctl`, правило перенаправления или опцию прокси, которая это исправит. В Linux порт 80
обычно означает одну команду:

```bash
echo 'net.ipv4.ip_unprivileged_port_start=80' | sudo tee /etc/sysctl.d/50-agentos.conf
sudo sysctl --system
```

Запуск сервера от root не рекомендуется — у агента настоящая оболочка.

Если **Ollama** работает, ваши локальные модели подхватываются автоматически. Добавьте облачные

> к инструментам** (любая модель `qwen*` или облачная модель). Более слабые локальные модели вроде
> `gemma` не будут надёжно вызывать инструменты.

## Запустить как ваш Linux-рабочий стол (SUI)

```bash
uv run bento installer      # определяет ваш дистрибутив, устанавливает недостающее, добавляет на экран входа
```

Затем выйдите из системы и выберите **Bento Box AI** на экране входа. Ваш существующий рабочий стол не
тронут — переключиться обратно — это выйти из системы и снова выбрать Ubuntu.

Установщик определяет дистрибутив, называет каждый пакет, который хочет, и почему, и спрашивает перед
установкой чего-либо. Две группы: движок композитора (sway и его друзья, MIT) и поверхность родного
рабочего стола (`python3-gi`, `python3-gi-cairo`, gtk-layer-shell, WebKitGTK), которая позволяет
рабочему столу быть настоящей поверхностью Wayland, а не окном браузера.

**Bento не поставляет и не распространяет ни один из них.** gtk-layer-shell — это MIT, но GTK,
PyGObject и WebKitGTK — это LGPL, а то, от чего этот проект *зависит*, остаётся пермиссивным — так что
их запрашивают, с лицензиями на виду. Без них сессия по-прежнему работает, отрисовывая рабочий стол в
окне Chromium. [Лицензирование →](../licensing.md) · [Интерфейс сессии →](../session-ui.md)

Если что-либо в рабочем столе ведёт себя неправильно, одна команда говорит вам почему:

```bash
uv run bento doctor --session   # проверяет, что действительно может отрисоваться на ЭТОЙ машине, и говорит об этом
```

Она проверяет интерпретатор, дисплей GTK, поддержку layer-shell композитором и то, может ли WebKit
отрисовывать *и продолжать отрисовывать* — в окне и на поверхности слоя — а затем выносит вердикт.
Проверки выполняются в подпроцессах, потому что сбои, которые она ищет, — это аварийные завершения и
segfault-ы, а проверка, которая роняет доктора, не может сообщить, что она упала.

## Установить как пакет Debian/Ubuntu (.deb)

Самодостаточный `.deb` (включает приложение **и** venv Python со всеми зависимостями — сеть при
установке не нужна):

```bash
./packaging/build-deb.sh                                   # → packaging/dist/agentos_<ver>_<arch>.deb
sudo dpkg -i packaging/dist/agentos_0.1.0_amd64.deb        # устанавливает в /opt/agentos + лаунчер + служба
systemctl --user enable --now agentos                      # запуск при входе (для каждого пользователя)
bento app                                                  # или запустить из меню
```

`apt`/`dpkg` занимаются обновлениями и удалением. Пакет **Recommends** `bubblewrap` (песочница) и
`xdg-utils`, а также **Suggests** `ollama`, `nodejs` и `git`. Пакет рабочего стола дополнительно
**Suggests** стек интерфейса сессии и `wayvnc`/`novnc` — предлагает, а не зависит, потому что apt
устанавливает Recommends по умолчанию, а это было бы поставкой в комплекте под более мягким именем.

## Установить как настоящее приложение (автозапуск при загрузке) — из исходников

```bash
uv run bento install      # лаунчер приложения + фоновая служба, запускающаяся при входе/загрузке
```

Правильный родной механизм используется автоматически: лаунчер `.desktop` плюс **пользовательская
служба systemd** в Linux (с linger, чтобы она запускалась при загрузке), пакет приложения плюс
**LaunchAgents** на macOS, ярлык в меню «Пуск» плюс **записи автозагрузки** в Windows.

Один набор команд управляет всеми тремя — вы не должны знать, использует ли эта машина systemd или
launchd, чтобы управлять собственным агентом:

```bash
bento service status       # запущено ли, вернётся ли при загрузке, отвечает ли порт
bento service start        # …stop, restart
bento service logs -f      # journalctl или файл журнала, что бы ни использовала эта машина
bento service uninstall    # удалить только фоновую службу — лаунчер и данные остаются
bento uninstall            # удалить лаунчер + службу (ваши данные остаются)
bento app                  # открыть как безрамочное окно рабочего стола в любой момент
```

`bento service status` сообщает, что считает супервизор, **и** отвечает ли порт, по отдельности:
юнит, который «активен», пока ничто не слушает, — это цикл падений, и именно это состояние стоит
иметь возможность видеть.

| Команда | Что она делает |

## Требования

- **Python ≥ 3.10** и [**uv**](https://docs.astral.sh/uv/) (или pip).
- **Провайдер модели** — либо [Ollama](https://ollama.com) локально (рекомендуется: модель, способная
  к инструментам, такая как `qwen3.5:9b`), либо облачный API-ключ.

Необязательное, разблокирует дополнительные функции при наличии — `bento installer` предлагает каждое
с его лицензией:

- **Linux-сессия (SUI)** — `sway` и его друзья, плюс `python3-gi`, `python3-gi-cairo`,
  `gir1.2-gtklayershell-0.1` и `gir1.2-webkit2-4.1`. [Подробности →](../session-ui.md)
- **wayvnc + novnc** — удалённый рабочий стол из браузера телефона, ретранслируемый по loopback.
- **bubblewrap** (`bwrap`) — **песочница** папки, которая запирает агента и терминал в одной папке.
- **Node/npx** и/или **uvx** — для запуска **MCP-серверов** (Playwright, filesystem, git, …).
- **git** — для установки **навыков** из репозиториев.

## Рабочий стол

- **Окна** — каждое приложение открывается в перетаскиваемом окне с изменяемым размером, с
  свернуть/развернуть/закрыть и z-упорядочиванием. **Панель задач** отслеживает открытые окна;
  **меню «Пуск»** запускает всё.
- **Окна, которые спят** — окно, которое вы не видите, перестаёт выполнять периодическую работу и
  обновляется в момент, когда возвращается. Шесть открытых и все свёрнутых приложений прошли путь от
  25 запросов за 10 с до 2.
- **Виртуальные рабочие столы** — пейджер на панели задач; `Ctrl+1..6` для переключения, правый клик
  для перемещения окна туда. Виджеты привязаны к рабочему столу, так что каждый — своё пространство.
- **Виджеты** — закрепите любое приложение как безрамочную живую плитку; перетаскивайте, меняйте
  размер, и оно восстанавливается при запуске.
- **Палитра команд** — `Ctrl+Space` (или `Ctrl+K`) для нечёткого запуска любого приложения или
  действия, или «Спросить Aria …», чтобы отправить прямо агенту. `Ctrl+Alt+T` открывает терминал.
- **Внешний вид** — обои, сгенерированные AI, с локальной галереей, анимация мышления, пока агент
  работает, и опциональный голос. Вставляйте изображения прямо в чат для моделей с поддержкой зрения.

## Что умеет агент

Агент (имя по умолчанию **Aria**) имеет большой набор инструментов и может управлять всей ОС из чата
или Telegram:

- **Действовать на машине** — выполнять команды оболочки, читать/писать файлы, получать веб-страницы,
  открывать приложения/файлы на хосте, уведомления рабочего стола.
- **Доставлять результаты** — `save_report` пишет стилизованный HTML-отчёт, который показывается в
  «Файлах» и открывается в вашем браузере, и может отправить сводку в Telegram. Агенту сказано
  **довести дело до конца** — превратить исследование в настоящий результат, а не останавливаться
  после поиска.
- **Строить ОС** — `create_app` создаёт новые UI-приложения с иконкой на рабочем столе; `pin_widget`
  размещает их на рабочем столе; `add_mcp_server` подключает новые каналы инструментов.
- **Расти** — двухуровневая память, граф знаний, `update_soul` — плюс **автообучение**: фоновый
  проход после каждого хода извлекает воспоминания и факты самостоятельно.
- **Автоматизировать** — `schedule_task` создаёт **задачи** без графики, которые доставляются в отчёт
  и/или Telegram.
- **Дополнять себя** — `read_source` / `develop_agentos` позволяют ему изменять **собственный
  исходный код** Bento; он сначала делает автоснимок и проверяет синтаксис перед записью.

Спрашивайте на обычном языке: *«добавь MCP-канал github», «собери мне трекер привычек и закрепи его
на рабочем столе 2», «каждое утро отчитывайся о трендах соцсетей в мой Telegram», «установи
inkscape».*

## Модели и провайдеры

- **Ollama** (локально) — автоматически обнаруживается; ничего не покидает вашу машину.
- **Anthropic**, **OpenAI**, **OpenRouter** или любой **совместимый с OpenAI** эндпоинт (LM Studio,
  vLLM, Groq, …).
- **Генерация изображений** — Google Gemini или модели изображений OpenAI, когда установлен ключ,

`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `OPENROUTER_API_KEY` и `GOOGLE_API_KEY` подхватываются
автоматически. Переключайте модели на лету из выпадающего списка окна чата.

## Безопасность

- **Уровни автономии** — «Параноик» / «Сбалансированный» автоматически выполняют действия только для
  чтения и спрашивают перед всем, что изменяет систему; «Полный» выполняет всё. Разрушительные команды
  **жёстко заблокированы** на каждом уровне.
- **Политики** — правила всегда-разрешить / всегда-запретить (с подстановочными знаками `*`),
  сопоставляемые с `<tool> <command>`.
- **Песочница папки** — с bubblewrap инструменты оболочки/файлов агента и терминал заперты в одной
  папке; остальная файловая система доступна только для чтения.
- **Снимки** — точки восстановления; агент делает автоснимок перед редактированием собственного кода.
- **Приватно по умолчанию** — привязывается к `127.0.0.1`. Удалённый доступ выключен, пока вы не
  включите его с паролем, а установка программного обеспечения отвергается откуда угодно, кроме самой
  машины.

## Telegram · MCP · Программируемость

**Telegram** — напишите @BotFather, вставьте токен в приложении Telegram, и первый приватный чат
становится владельцем. У агента там есть все его инструменты; рискованные действия отправляют встроенные
кнопки «Разрешить»/«Запретить».

**MCP-серверы** — добавьте внешние серверы инструментов из каталога (Playwright, filesystem, fetch,
git, GitHub, Postgres, Slack, поиск, …) или собственный сервер `stdio`/`http`. Их инструменты
появляются агенту как `mcp_<server>_<tool>`, а собранным приложениям — через `POST /api/tool`.

**Программируемость** — `bento ask "…"` для одноразовых запусков; REST API (`POST /api/chat`,
`GET /api/system`, `POST /api/tool`, …); WebSocket-ы на `/ws` (потоковый чат + подтверждения) и
`/ws/terminal` (PTY хоста). Приложения, которые вы создаёте, работают в iframe того же источника и
могут вызывать всё это.

## Архитектура

```
agentos/                 # пакет Python сохраняет своё исходное имя; см. «О названии» ниже
├── __main__.py    # точка входа CLI: serve · app · installer · doctor · apps · remote-desktop · ask
├── agent.py       # ядро: цикл план → действие (инструменты) → наблюдение, шлюзы подтверждения, персоны
├── providers.py   # унифицированный потоковый чат: Ollama / Anthropic / OpenAI / OpenRouter / custom
├── tools.py       # руки: оболочка, файлы, веб, приложения, отчёты, память, KG, душа, навыки, MCP
├── shellhost.py   # SUI: рабочий стол как поверхность wlr-layer-shell (GTK + WebKitGTK)
├── sessiondoctor.py # что действительно может отрисовать рабочий стол на этой машине
├── compositor.py  # IPC sway/wlroots: окна, рабочие пространства, выходы, живые события
├── appstore.py    # установка родных приложений через appstream / flatpak / apt
├── remotedesktop.py # браузерный удалённый рабочий стол, ретранслируемый по аутентифицированному соединению
├── installer.py   # настройка с учётом ОС: определить дистрибутив, установить недостающее, сначала спросить
├── memory.py      # SQLite: разговоры, воспоминания, задачи, журналы, KG, навыки, приложения
├── server.py      # FastAPI: UI рабочего стола, REST API, потоки WebSocket, обслуживание файлов
└── ui/
    ├── src/       # исходники рабочего стола — редактируйте здесь
    └── index.html # генерируется `python -m agentos.ui.build` (не редактировать)
```

**Состояние живёт в `~/.agentos/`:** `config.json`, база данных SQLite, `soul.md`, `wallpapers/`,
`snapshots/`. Рабочий каталог агента — `~/AgentOS/`.
